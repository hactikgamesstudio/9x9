#### BotController.cs
**Purpose:** Individual bot AI controller  
**Location:** `Assets/Bots/BotController.cs`  
**Namespace:** `Unity.Template.Multiplayer.NGO.Bots`

**Features Implemented:**
- **Movement System:**
  - Autonomous navigation to random waypoints
  - Smooth rotation towards targets (configurable rotation speed)
  - CharacterController-based movement with gravity
  - Waypoint reached detection (0.5 unit threshold)

- **AI Behavior:**
  - Player detection within configurable range (default: 10 units)
  - Pursuit behavior when player detected
  - Path updates every 0.5 seconds
  - Stuck detection every 2 seconds (movement threshold: 0.1 units)
  - Automatic recovery when stuck (new random target)

- **Combat System:**
  - Attack range: 2 units (configurable)
  - Damage: 10 per attack (configurable)
  - Attack cooldown: 1 second (configurable)
  - Target nearest player within detection range

- **Health & Death:**
  - Health: 100 HP
  - TakeDamage() method for player/hazard damage
  - Death handling with BotManager notification
  - Deactivates on death

- **Debug Tools:**
  - Gizmos for detection range (yellow sphere)
  - Gizmos for attack range (red sphere)
  - Current target visualization (green line and sphere)

**Configuration Options:**
- Bot Name, Bot ID
- Move Speed (3), Rotation Speed (5)

- Attack Range (2), Detection Range (10), Damage (10), Attack Cooldown (1)

## Technical Decisions

### Why Separate Game/Core/Bots?
1. **Modularity:** Bots can be enabled/disabled independently
2. **Clear Dependencies:** Core has no game-specific logic, Game builds on Core
3. **Easier Testing:** Each module can be tested in isolation
4. **Future Multiplayer:** Bots can be synced over network later
5. **Cleaner Git:** Changes to gameplay don't touch core systems

### Why Not NavMesh Yet?
- Start with simple pathfinding to get working prototype
- NavMesh requires baked navigation data
- Room generation is dynamic (9×9×9 grid)
- Will add NavMesh in future iteration once rooms are stable

### Bot AI Design Philosophy
- **Simple but Functional:** Direct-line movement, basic combat
- **Debuggable:** Gizmos, logs, inspector-visible state
- **Configurable:** All parameters exposed in Inspector
- **Extensible:** Easy to add features (item pickup, puzzle solving, etc.)
