**Result**: Cleaner menu system with straightforward Unity UI workflow, no more UI Toolkit conflicts.

### 4. EventSystem Conflicts

**Issue Identified**: Multiple EventSystem components causing Unity runtime warning.

#### Root Cause:
- MetagameApplication prefab contains EventSystem (for new UI)
- MenuScene.unity also has standalone EventSystem
- Both active simultaneously when loading scenes

**Temporary Solution**: 
- Added `PruneDuplicateEventSystems()` in CustomNetworkManager
- Keeps first EventSystem, destroys duplicates on game app instantiation

**Permanent Solution** (scheduled for next session):
- Deactivate MenuScene EventSystem (not primary scene)
- Keep MetagameApplication EventSystem as single source of truth

## Technical Decisions

### UI System Choice: uGUI over UI Toolkit

**Rationale**:
- uGUI more stable and mature for Unity 6
- Better Inspector integration for rapid prototyping
- Fewer input system conflicts
- Team familiarity with Canvas workflow
- UI Toolkit reserved for runtime debugging tools if needed

### Profile System Architecture

**Design**:
- ScriptableObject-based for Unity editor integration
- JSON serialization for cross-platform save files
- Singleton manager pattern for global access
- Future-ready for cloud save integration

## Lessons Learned

1. **uGUI Stability**: For menu systems, traditional Unity UI provides faster iteration and fewer surprises than UI Toolkit in Unity 6.

2. **EventSystem Management**: Only one EventSystem should be active per scene hierarchy; prefer single source in application root.

3. **Cleanup Strategy**: Document before deleting; keep template code as reference even if not actively used.

4. **Profile Architecture**: ScriptableObjects + JSON gives best of both worlds (editor integration + persistence).
